# MikroORM (Database & Entities)

**When to use**: when adding entities, creating migrations, or modifying ORM configuration.

**Key points**:

1. **Entity placement**: `src/modules/<module>/entities/<name>.entity.ts`. Discovered by `entitiesTs: ['src/**/*.entity.ts']` in mikro-orm.config.ts. Never place entities outside `modules/` or mix them with non-entity files.
2. **Migration placement**: source in `src/infra/database/migrations/`, compiled in `dist/infra/database/migrations/`. Generated by `pnpm mikro-orm:migration:create`. CLI runs `.ts` via tsx; production runs compiled `.js`.
3. **Dependency versions**: all MikroORM packages use `catalog:backend` in `pnpm-workspace.yaml`. Never pin a raw version — add to the catalog instead.
4. **CLI env injection**: `mikro-orm:*` scripts inject root `.env` via `dotenv-cli`. Run through `pnpm mikro-orm:*` scripts, never bare `mikro-orm` CLI (env won't load).
5. **`@InjectMikroORM('default')` for DI**: v7 requires a name parameter. Always pass `'default'` (the default MikroORM context name). Omitting it causes `Expected 1 arguments, but got 0` type error.
6. **ESM-only packages**: `@mikro-orm/nestjs` is ESM-only. Jest CJS tests cannot import it directly — mock it with `jest.mock('@mikro-orm/nestjs', ...)` before importing the module under test.
7. **Schema diff**: `schemaGenerator.ignoreSchema` excludes Supabase system schemas (auth, storage, realtime, etc.) from `migration:create`. Never add business schemas to this list.

**Example**:

```ts
// Entity
@Entity()
export class Agent {
  @PrimaryKey()
  id: string = crypto.randomUUID()

  @Property()
  name!: string
}

// Migration (via CLI)
// pnpm mikro-orm:migration:create
```

**Verification**:

```bash
rg -n 'catalog:backend' apps/server/package.json
# All MikroORM packages use catalog protocol
pnpm --filter server mikro-orm:debug
# Connection and entity discovery pass
```
