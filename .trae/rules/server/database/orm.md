# MikroORM (Database & Entities)

**When to use**: when adding entities, creating migrations, or modifying ORM configuration.

**Key points**:

1. **Entity placement**: `src/modules/<module>/entities/<name>.entity.ts`, discovered by `entitiesTs: ['src/**/*.entity.ts']`. Entities are `defineEntity` Entity Schemas (mirror existing ones) with a `to<Entity>` / `toRow` mapping pair for contract conversion — not class decorators.
2. **contextName consistency**: mikro-orm.config declares `contextName: 'default'`. Every domain module's `MikroOrmModule.forFeature([...])` MUST pass the same `'default'` — without it, repository providers inject the `EntityManager` class token while forRoot exports the `default_EntityManager` string token, and the app fails at boot.
3. **EM lifecycle**: `registerRequestContext: false` (no per-request EM). Services inject `@InjectMikroORM('default')` (the MikroORM instance) and call `this.orm.em.fork()` per operation. `em.persist(em.create(...))` — `em.create` alone never enters the persistence context. Multi-write operations use `em.transactional((tem) => ...)`; pass the transactional `tem` into cross-domain services (e.g. audit) so they commit atomically.
4. **Migration placement**: source in `src/infra/database/migrations/`, compiled in `dist/infra/database/migrations/`. Generated by `pnpm mikro-orm:migration:create`. CLI runs `.ts` via tsx; production runs compiled `.js`.
5. **Dependency versions**: all MikroORM packages are declared in the `backend` catalog. Exact pins are allowed only with a reason comment in `pnpm-workspace.yaml` (e.g. `'@mikro-orm/core': 7.1.11` — the `^7.1.11` range floated to a broken 7.1.14).
6. **CLI env injection**: `mikro-orm:*` scripts inject root `.env` via `dotenv-cli`. Run through `pnpm mikro-orm:*` scripts, never bare `mikro-orm` CLI (env won't load).
7. **ESM**: the server compiles to ESM (`"type": "module"`) and `@mikro-orm/*` is ESM-only — imports resolve natively, no interop shims.
8. **Schema diff**: `schemaGenerator.ignoreSchema` excludes Supabase system schemas (auth, storage, realtime, etc.) from `migration:create`. Never add business schemas to this list.

**Example**:

```ts
// Entity — Entity Schema style, mirroring existing entities
export const AgentEntity = defineEntity({
  name: "AgentRecord",
  tableName: "agents",
  properties: (p) => ({
    id: p.text().primary(),
    name: p.text(),
    createdAt: p.datetime(),
    updatedAt: p.datetime(),
  }),
  indexes: [{ properties: ["name"] }],
});

// Migration (via CLI)
// pnpm mikro-orm:migration:create
```

**Verification**:

```bash
pnpm --filter server mikro-orm:debug
# Connection and entity discovery pass
rg -n "forFeature\(\[" apps/server/src/modules
# Every call carries the 'default' contextName
```
