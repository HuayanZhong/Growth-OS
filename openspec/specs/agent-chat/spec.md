# agent-chat

## Purpose

定义 agent 会话视图的静态行为契约：开场页与聊天态的双态布局、发送时输入框停靠底部的过渡动画、按 agent 的会话内存缓存，以及新任务页向 agent 会话的首条消息交接。agent 回复经 `POST /chat/stream` 以流式增量呈现。

## Requirements

### Requirement: Agent 页双态布局

Agent 页 SHALL 依据会话状态呈现两种布局：无会话时呈现 hero 态（问候语 + 居中输入区）；已有会话时呈现 chat 态（上方可滚动消息流 + 停靠于内容区底部的输入区，输入区宽度撑满内容区并留边距，消息列与输入区同宽同左缘）。两种布局切换时页面不得闪烁或出现中间态。

#### Scenario: 无会话进入呈现 hero 态

- **WHEN** 用户从侧边栏进入一个尚无会话的 agent 页
- **THEN** 页面呈现问候语与居中输入区，无消息流

#### Scenario: 有会话进入直接呈现 chat 态

- **WHEN** 用户从侧边栏进入一个已有会话的 agent 页
- **THEN** 页面直接呈现消息流与底部停靠输入区，不经过 hero 态，且消息内容与离开时一致

#### Scenario: chat 态不渲染 Agent 选择垫层

- **WHEN** Agent 页处于 chat 态（含停靠过渡完成后）
- **THEN** 底部输入区不包含 agent 选择垫层（切换 agent 仅通过侧边栏）；hero 态输入区仍带该垫层

#### Scenario: chat 态顶部元信息

- **WHEN** Agent 页处于 chat 态
- **THEN** 页面顶部固定呈现当前 agent 名称与在线状态；消息流顶部居中呈现「对话由AI生成」声明与日期分割线（取首条消息时间，M-DD 格式），二者随消息流滚动

#### Scenario: 消息带身份行

- **WHEN** 消息流渲染任意消息
- **THEN** 每条消息上方呈现头像与发送者名称（用户侧为登录邮箱、agent 侧为目录名称并额外带「AI」徽章），消息体位于灰色气泡内并按身份行缩进对齐，两侧均靠左

#### Scenario: 点击顶栏名字弹出 Agent 信息卡

- **WHEN** chat 态点击顶栏的 agent 名称
- **THEN** 弹出信息卡：居中大头像、agent 名称、「AI Agent · 在线」身份、已开启技能数量与技能标签；不包含发消息/新项目按钮与渠道区块

### Requirement: 发送驱动的停靠过渡

在 hero 态发送消息时，系统 SHALL 以输入框从居中原位平滑位移到停靠位的过渡动画切换到 chat 态；过渡期间问候语淡出、消息流淡入；过渡完成后元素无内联 transform/opacity 残留。动画中途页面卸载不得产生残留或报错。

#### Scenario: hero 态发送触发位移动画

- **WHEN** 用户在 hero 态输入内容并点击发送
- **THEN** 输入框从居中位置平滑移动到底部停靠位，问候语淡出消失，用户消息出现在消息流中，输入框草稿清空且可继续输入

#### Scenario: 过渡完成无残留

- **WHEN** 停靠过渡动画播放完成
- **THEN** 动画目标元素的内联 transform/opacity 样式被清除（computed style 为初始值）

#### Scenario: 过渡期间离开页面

- **WHEN** 停靠过渡动画进行中用户切换到其他页面
- **THEN** 无报错，无样式残留泄漏到其他页面

### Requirement: 会话按 agent 内存缓存

会话内容 SHALL 按 agent 标识在应用运行期间保留在内存中：同一应用会话内切换页面后返回，消息保留；应用重启后会话清空。会话数据不得持久化到磁盘或远端。

#### Scenario: 切换后返回内容保留

- **WHEN** 用户在 agent A 存在会话时切到其他页面，再从侧边栏返回 agent A
- **THEN** agent A 的消息流内容与离开时完全一致

#### Scenario: 重启后会话清空

- **WHEN** 用户重启应用后进入此前有过会话的 agent 页
- **THEN** 页面呈现 hero 态（无缓存会话）

### Requirement: 发送追加消息与流式回复

用户在 chat 态（或过渡后）每次发送 SHALL 立即追加一条用户消息，并发起 `POST /chat/stream` 的流式请求；agent 侧气泡 SHALL 先呈现等待指示，收到首个文本增量后切换为文本内容并随增量增长（打字机效果）。渲染 SHALL 按事件到达顺序追加，顺序拼接即为完整回复。回复生成进行中，新的发送 SHALL 被忽略（消息顺序保护）。

#### Scenario: 发送后开始流式回复

- **WHEN** 用户在 chat 态发送一条消息
- **THEN** 消息流末尾追加该用户消息，agent 侧先呈现等待指示，随后气泡内文本随增量逐段出现直至回复完成

#### Scenario: 增量顺序渲染

- **WHEN** 流式回复进行中
- **THEN** 气泡内文本严格按增量到达顺序增长，无乱序、无重复、无丢失

#### Scenario: 回复完成后可继续追问

- **WHEN** 一次流式回复完成后用户发送新消息
- **THEN** 新请求携带包含上一轮的完整会话历史，回复内容体现对上文的记忆

#### Scenario: 生成中发送被忽略

- **WHEN** 回复生成进行中用户尝试发送新消息
- **THEN** 该次发送不入列、不开启新请求，进行中的回复不受影响

### Requirement: 停止生成

回复生成进行中，聊天界面 SHALL 呈现停止操作（发送按钮变停止样式）；用户触发停止 SHALL 中止流式请求，气泡 SHALL 保留已收到的部分文本，会话 SHALL 可继续发送新消息。

#### Scenario: 点击停止保留部分回复

- **WHEN** 回复生成进行中用户触发停止
- **THEN** 流式请求被中止，agent 气泡保留已收到的文本且不再增长

#### Scenario: 停止后可继续发送

- **WHEN** 用户停止一次生成后发送新消息
- **THEN** 新消息正常发送并开始新的流式回复

### Requirement: 流式错误呈现

流式请求失败或收到 `error` 事件时，界面 SHALL 呈现用户可感知的错误提示；已收到的部分回复文本 SHALL 保留，输入区 SHALL 保持可用；鉴权失效 SHALL 沿用既有会话过期处理（本地登出降级）。

#### Scenario: 服务端 error 事件

- **WHEN** 流式回复进行中收到 `error` 事件
- **THEN** 呈现错误提示，已收到的部分文本保留，输入区可继续发送

#### Scenario: 请求建立失败

- **WHEN** 流式请求未能建立（网络错误或非 2xx 响应）
- **THEN** 呈现错误提示且会话可继续发送新消息

#### Scenario: 会话过期

- **WHEN** 流式请求因 JWT 失效返回 401
- **THEN** 按既有规则执行本地登出降级

### Requirement: 新任务页向 agent 会话交接

新任务页发送时，系统 SHALL 携带输入内容跳转到当前所选 agent 的页面，该页 SHALL 直接以 chat 态呈现且首条用户消息已出现在消息流中（无 hero 态闪现，无停靠位移动画）。

#### Scenario: 新任务页发送落入 agent 会话

- **WHEN** 用户在新任务页（所选 agent 为小花颜）输入内容并发送
- **THEN** 应用跳转到小花颜的 agent 页，页面直接呈现 chat 态，消息流中已包含该条消息

### Requirement: 图片输入与附件卡片

聊天输入区 SHALL 支持两种图片入口：在输入框内粘贴剪贴板图片（Ctrl+V），以及通过附件按钮打开文件选择器（限定 JPEG/PNG/GIF/WebP）。图片就绪后 SHALL 在输入卡片内部顶部呈现附件卡片：缩略图、文件名（剪贴板图片无文件名时自动生成）、格式标签与删除按钮；删除 SHALL 仅移除该卡片，不影响草稿文本。文本粘贴行为 SHALL 不受影响。超过大小上限的图片 SHALL 被拒绝并以用户可感知的提示说明原因；无法解码的损坏图片 SHALL 同样被拒绝且不影响已就绪的附件。

#### Scenario: 粘贴截图出现附件卡片

- **WHEN** 用户向输入框粘贴一张剪贴板截图
- **THEN** 输入卡片内部顶部出现该图片的附件卡片（缩略图 + 自动生成文件名 + 格式标签 + 删除按钮），草稿文本区可继续输入

#### Scenario: 附件按钮打开文件选择

- **WHEN** 用户点击附件按钮并选择一张支持的图片
- **THEN** 与粘贴一致地出现附件卡片

#### Scenario: 文本粘贴不受影响

- **WHEN** 用户向输入框粘贴纯文本
- **THEN** 文本按常规行为插入光标处，不产生附件卡片

#### Scenario: 超大图片被拒绝

- **WHEN** 用户粘贴或选择超过大小上限的图片
- **THEN** 该图片不入卡，呈现明确的拒绝提示，已有附件与草稿不受影响

#### Scenario: 损坏图片被拒绝

- **WHEN** 用户粘贴一张无法解码的图片数据
- **THEN** 呈现拒绝提示，已就绪的附件卡片保留，输入区正常可用

#### Scenario: 删除附件卡片

- **WHEN** 用户点击某附件卡片的删除按钮
- **THEN** 该卡片移除，其余附件卡片与草稿文本保持不变

### Requirement: 图片消息发送与渲染

含图片的消息 SHALL 与文本消息共用发送门槛：文本或附件任一非空即可发送，发送后附件卡片清空；回复生成进行中的发送忽略保护 SHALL 同样覆盖含图消息。用户气泡 SHALL 以图 + 文本混排呈现（无文本时可仅有图）。后续轮次发送时历史 SHALL 完整重发，模型 SHALL 可继续引用此前轮次中的图片内容；图片仅驻留应用内存，随会话清空而消失，不持久化。

#### Scenario: 仅发图片无文本

- **WHEN** 用户只贴图不输入文字并点击发送
- **THEN** 发送成功，消息流出现仅含图片的用户消息，agent 开始流式回复

#### Scenario: 图文混排气泡

- **WHEN** 用户发送附带文字的图片消息
- **THEN** 用户气泡内同时呈现图片与文字

#### Scenario: 生成中发送含图消息被忽略

- **WHEN** 回复生成进行中用户尝试发送含图片的消息
- **THEN** 该次发送被忽略（与纯文本消息同规则），附件卡片保留

#### Scenario: 追问引用先前图片

- **WHEN** 用户发送图片获得回复后，追问与该图相关的问题
- **THEN** 回复内容体现模型仍可访问先前轮次的图片

#### Scenario: 会话清空后图片消失

- **WHEN** 用户重启应用后进入此前发过图的会话
- **THEN** 会话为空（遵循内存会话既有行为），无残留图片引用

### Requirement: 模型切换分割线

chat 态下用户切换模型时，消息流 SHALL 立即插入居中分割线并标注新模型名称（如「已切换至 DeepSeek」）；分割线为会话元信息，SHALL 不进入请求历史。重复选择相同模型 SHALL 不重复插入；从其他模型切回亦呈现分割线；无会话（hero 态/新任务页）时切换 SHALL 不产生分割线。

#### Scenario: 会话中切换模型出现分割线

- **WHEN** chat 态下用户将模型从 Auto 切换为 DeepSeek
- **THEN** 消息流末尾立即出现居中分割线并标注「已切换至 DeepSeek」，后续消息在其下

#### Scenario: 重复选择相同模型不插线

- **WHEN** 当前生效模型已是 DeepSeek，用户再次选择 DeepSeek
- **THEN** 消息流无新增分割线

#### Scenario: 切回呈现分割线

- **WHEN** 用户从 DeepSeek 切换回 Auto
- **THEN** 消息流出现「已切换至 Auto」分割线

#### Scenario: 分割线不进入请求历史

- **WHEN** 分割线插入后用户发送新消息
- **THEN** 请求体消息历史不含分割线条目，仅含 text/typing 之外的正式消息

#### Scenario: 无会话切换无分割线

- **WHEN** hero 态（或新任务页）用户切换模型
- **THEN** 不产生任何分割线（首次发送仍按所选模型路由）
