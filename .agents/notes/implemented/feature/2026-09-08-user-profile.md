# Agent Note: 用户画像机制（agent 自我个性化）

Status: implemented

## Problem

agent 对用户的适配靠会话记忆与用户全局规则，跨会话不持久、粒度粗：全局规则编码的是用户写死的标准（协作方式、验证顺序等），而交互中观察到的稳定习惯（推进方式、决策偏好、越界边界、提交所有权）没有承载与复用机制，每次会话都要重新摸索。

## Decision

- **规则与数据分离**：采集标准/分类体系/识别规则/置信度计分/特殊场景/质量标准进 `.trae/rules/agent/user-profile.md`（英文 SSOT，智能生效）；画像数据是活文档 `.agents/user-profile.md`（中文，五类固定分区：代码风格/问题解决路径/技术栈/沟通模式/工作流习惯）。
- **置信度 1–5 计分**：5=用户成文规则（引用不复制）、4=重复显式陈述或纠正、3=≥2 次一致行为、2=单次观察、1=弱信号；仅 ≥3 影响默认行为。调整：佐证 +1（上限 5）、矛盾 −2 并标 conflict、30 天未动 −1。precedence 链：系统/安全 → 用户最新指令 → 成文规则 → 画像（≥3）→ agent 默认。
- **采集门槛**：明文陈述立即入档；行为推断需 ≥2 次独立观察；禁止记录凭证/隐私/业务数据内容；已被规则编码的偏好只引用不复制（one fact, one home）。
- **特殊场景**：用户纠正 → 立即入档置 4；画像与最新指令冲突 → 指令优先、事后降级；敏感内容拒录；多人观察按 owner 区分；画像损坏从空模板重建。
- **初始化**：画像以本会话真实观察起档（推进方式 4、越界敏感 4、升级决策模式 4、提交所有权 4、harness 防腐 4、决策选项化 3、先评估后动手 3、IDE 并行编辑注意 3），每条带 evidence 与 last_updated。

## Alternatives considered

- 画像数据 YAML：更机器友好，但人读/diff/手工编辑体验差，且消费方是 agent 自身——Markdown 固定分区即可解析。
- 自动 hook 在 PostToolUse 提炼信号：信号判断是语义任务，机器规则无法可靠提取；采用"任务收尾时 agent 按 rule 审视"的软机制。
- 画像并入用户全局规则：全局规则是用户写死的稳定标准（每个会话注入），画像按会话演化——混入会让规则文件失去权威性与预算可控性。

## Consequences

- 根 AGENTS.md 新增 User profile 节（standing order）；guide-zh 增加 Agent 协作组（预算提至 1080）。
- 画像文件在 `.agents/` 下，不受 verify-docs 门禁，但受规则约束（evidence/last_updated/conflict 字段、禁密钥）；结构损坏从空模板重建，不猜测。
- 每次实质任务收尾审视信号；用户明确纠正即时入档。
